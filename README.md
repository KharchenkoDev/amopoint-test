Тестовое задание: [ссылка](https://docs.google.com/document/d/10LwR5k3guN9Z45-6lnQXcdN53R17Q4keoT01mMkW4hA/edit?tab=t.0)

Проект опубликован по адресу: [amopoint.it-dude.ru](https://amopoint.it-dude.ru)

## Запуск

**1. Скопируй `.env`-файлы**

```bash
cp .env.example .env
cp src/.env.example src/.env
```

**2. Заполни переменные в `.env` и `src/.env`**

В `src/.env` укажи API-ключ CoinGecko:

```dotenv
COINGECKO_API_KEY=your_key_here
```

И логин с паролем для входа в админку статистики:

```dotenv
STATS_USER=admin
STATS_PASSWORD=your_password_here
```

**3. Запусти установку**

```bash
make install
```

**Для работы с проектом**

```bash
make up      # запустить контейнеры
make down    # остановить
```

## 1. CoinGecko Price Tracker

Приложение периодически получает курсы криптовалют (bitcoin, ethereum, tether) из CoinGecko API и сохраняет историю в базу данных. Доступ к данным — через REST API с пагинацией.

### Комментарии к реализации

- В качестве источника данных выбран CoinGecko API с курсами криптовалют. Это мне показалось несколько полезнее и ближе к реальным задачам, чем сервис с анекдотами из примера к заданию.
- Для запуска проекта нужен API-ключ CoinGecko. Его можно получить бесплатно, зарегистрировав демо-аккаунт на [coingecko.com](https://www.coingecko.com/). Ключ указывается в `src/.env`.
- Консольная команда не обращается к API напрямую, а запускает Job. Подобная логика в реальных проектах почти всегда требует очередей. Это позволяет повторять задачи при ошибках, распределять нагрузку и не блокировать основной процесс.
- API отдаёт данные постранично. Без пагинации база данных со временем накопила бы достаточно записей, чтобы один запрос без ограничений начал создавать проблемы.

## API

### `GET /api/prices`

Возвращает историю цен с пагинацией.

**Параметры запроса**

| Параметр   | Тип     | По умолчанию | Описание                                            |
|------------|---------|--------------|-----------------------------------------------------|
| `coin_id`  | string  | —            | Фильтр по монете: `bitcoin`, `ethereum`, `tether`   |
| `per_page` | integer | 50           | Записей на страницу (макс. 500)                     |
| `page`     | integer | 1            | Номер страницы                                      |

**Пример ответа**

```json
{
  "data": [
    {
      "id": 1,
      "coin_id": "bitcoin",
      "price_usd": "81236.00000000",
      "fetched_at": "2025-04-10T12:00:00.000000Z",
      "created_at": "2025-04-10T12:00:01.000000Z"
    }
  ],
  "current_page": 1,
  "per_page": 50,
  "total": 1440,
  "last_page": 29
}
```

## 3. Трекер посещений

Состоит из JS-скрипта, который отправляет данные на сервер. И серверной части, которая определяет город, устройство, записывает данные в базу. Так же есть админка, где можно посмотреть статистику.

### Комментарии к реализации

- Город намеренно определяется на бэкенде, а не на фронтенде. На фронтенде определять город нет смысла. Во-первых, для этого всё равно пришлось бы делать запрос на бекенд (лишний). Во-вторых, нет смысла доверять тому, что пришло с фронта. Проще и надёжнее определять город по IP. (*Ещё можно реализовать получение географическийх координат через API браузера и уточнять у пользователя его город, но это уже выходит за рамки данного тестового задания.*)
- Для GeoIP используется бесплатный API [ip-api.com](http://ip-api.com). Результаты кешируются.
- Тип устройства определяется парсингом `User-Agent` на сервере.
- Статистика защищена авторизацией. Логин и пароль задаются в `src/.env` через `STATS_USER` и `STATS_PASSWORD`.

### `GET /stats`

Страница статистики с двумя графиками: уникальные визиты по часам за последние 24 часа и разбивка по городам.

### `POST /api/track`

Эндпоинт для приёма данных от трекера. Открыт для cross-origin запросов (CORS).

### Подключение к сайту

```html
<script>window.TRACKING_URL = 'https://amopoint.it-dude.ru/api/track';</script>
<script src="https://amopoint.it-dude.ru/js/tracker.js"></script>
```
